# TC135-TC140 Performance Matrix (2026-07-28)

## Scope

- Topology: 3 nodes, 1 socket per node (`--1s`).
- Profiles: `naive`, `spill-noopt`, and `spill-opt`.
- Guest counter: ARM `cntvct_el0`, 25,165,824 Hz (39.736 ns per counter tick).
- Guest latency markers contain fixed-buffer min/p50/p95/p99/max/mean data.
- TC139 throughput is independently measured as completed mixed operations per
  guest-counter second. It is not derived by taking the inverse of a latency
  value.
- `EP-PERF kind=outer` remains a protocol-only diagnostic. Its mean covers all
  completed outer transactions in the workload, not only the timed guest phase.

## Policy Activity

- Naive directory-pressure workloads produced forced evictions: TC135-TC138
  each recorded 256 naive evictions; revised TC139 recorded 488.
- Spill workloads produced 180-203 spill starts in TC135-TC138 and 185 in
  revised TC139, plus H64 fills on the new-requester and handoff paths.
- TC140 produced no directory spill/eviction activity, as intended.
- No `SILENT` or `BATCH-RS` event marker was observed in TC135-TC140. Therefore
  the near-identical `spill-noopt` and `spill-opt` values must not be attributed
  to a measured optimization hit.

## Acceptance Interpretation

- The >=10% optimized-vs-naive outer-latency target is met by TC135, TC136,
  TC137, and TC139.
- It is not met by TC138, where the spilled dirty-owner handoff is 10.44%
  slower at the outer boundary and 12.12% slower at the guest boundary.
- TC140 is neutral and does not demonstrate silent-upgrade benefit.
- Preserved-copy reuse is the dominant spill benefit: TC135, TC136, and TC139
  improve guest-visible mean latency by 87.88%-90.77%.
- A new requester still benefits in TC137, but only by 21.54%, because H64
  metadata onload and coherence work remain on the critical path.
- `spill-opt` does not materially outperform `spill-noopt` in this matrix.
  Additional optimization-specific workloads or confirmed optimization event
  counters are required before claiming a batch-RS or silent-upgrade gain.

## TC139 Initial Failure

The first TC139 version converted pressured shared lines directly into stores.
Both spill profiles timed out after 3600 seconds while naive completed.

The logs show a repeatable protocol state gap:

1. `UpgradeReq` for PA `0x10500040` caused an H64 fill.
2. The restored entry had `sharersMask=0x0`.
3. The requester upgrade was rejected as not being a sharer.
4. Two resident waiters remained permanently queued while outstanding and
   pending-requester counts were zero.

Evidence is retained under:

- `logs/tc135_perf_matrix_20260728_all/spill-noopt/tc139/`
- `logs/tc135_perf_matrix_20260728_all/spill-opt/tc139/`

The revised throughput workload establishes odd lines as node1-owned before
pressure, while even lines remain shared-read lines. This measures the intended
preserved-sharer/preserved-owner mixed workload without hiding the initial
upgrade-after-fill defect.

The defect is now covered by correctness regression TC141. The fix consists of:

- `G_S` delayed data writeback removes only the releasing node's sharer bit and
  preserves all other live sharers.
- `G_E` rejects WritebackReq; clean exclusive release must use EvictReq.
- `G_M` WritebackReq requires a dirty payload.
- Upgrade requests deferred by Resident fill/capacity no longer receive an
  early temporary response. Resident replay pushes the accepted UpgradeResp for
  the original reqId.
- Permanent NotSharer Upgrade waiters and stale Writeback waiters are removed
  instead of remaining pinned forever.

Post-fix validation:

- TC141 spill-noopt: PASS.
- TC141 optimized: PASS.
- TC127 dirty writeback persistence: PASS.
- TC128 clean offload/onload: PASS after accepting the existing safe
  force-remove marker as valid clean-offload evidence.
- TC129 two-cycle spill/fill and ownership transition: PASS.

## Result

- Final valid matrix: 18/18 profile/test combinations passed correctness and
  metric verification.
- Initial TC139 shared-to-writer variant: 1/3 passed (naive); both spill
  profiles exposed a reproducible resident-waiter liveness defect.
- Spill reuse benefits are large and visible only with the new guest-facing
  first-revisit and independent mixed-throughput metrics.
