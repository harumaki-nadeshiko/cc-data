# TC217 HA10 2N1S Performance Result (2026-07-28)

## Scenario

- Portable core: `tests/e2e/workloads/e2e_ha_2n1s_core.c`.
- Topology: two nodes, one socket per node.
- ResidentDir: 512 entries (1-way x 512-set).
- Working set: 16 catalog lines plus 640 streamed pressure lines (41,984 B).
- Measured work: eight batches; each batch has 14 skewed reads and two updates.
- Correctness: both nodes emit successful HA10 validation; node0 verifies the
  final values of both update keys.
- Guest timing: ARM CNTVCT at 25,165,824 Hz.

## Results

| Profile | Mean 16-op batch | P50 | P99 | Mean ns/op | Useful ops/s |
|---|---:|---:|---:|---:|---:|
| naive | 7,987.02 ns | 7,748.60 ns | 13,391.18 ns | 500.74 ns | 1,997,040 |
| spill-noopt | 4,212.06 ns | 4,172.33 ns | 4,450.48 ns | 263.88 ns | 3,789,677 |
| optimized | 4,212.06 ns | 4,172.33 ns | 4,490.22 ns | 264.19 ns | 3,785,224 |

Optimized relative to naive:

- Mean guest latency per useful operation: -47.24%.
- Useful throughput: +89.54%.
- Both baseline and optimized runs passed all correctness checks.

This is a baseline-above-500-ns scenario and therefore contributes a passing
sample to metric 2's average reduction calculation.
