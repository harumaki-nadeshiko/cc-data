# FV2: Epoch Monotonicity and sharersMask Invariants

| Invariant | Source Location | Mechanism | Enforcement |
|-----------|----------------|-----------|-------------|
| **Epoch monotonic advance by 1 per commit** | `allocateReservedEpoch` (L2183): `entry.epoch + 1` → `ost.reservedEpoch`; `commitIntendedResult` (L2200): `entry.epoch = ost.reservedEpoch` | Reserved epoch = committed + 1 (mod `2^_epochBits`); only Clear commit modifies `entry.epoch` | `checkEpochForLine` (L1466) + `isNewerEpoch` (L2157): rejects any message whose epoch is strictly older than committed epoch via half-range comparison |
| **No stale message advances state** | `processInvalidationAck` (L1234–1243), `processWriteback` (L1656), `processClearDrop` (L2037) | All epoch-bearing message handlers call `checkEpochForLine` before mutating directory | `_staleRejectedCount` counter incremented on rejection; stale `GRANT_HANDSHAKE` retired via `retireToTombstone` (L2048) |
| **G_E/G_M ⇒ popcount(sharersMask) = 1** | `ResidentDir::validateCanonical` (L151–157); `commitIntendedResult` (L2205–2207) | `canonicalOneHotRequired` returns true for G_E/G_M; `panic_if(popcount != 1)` | Double panic: at write-back to ResidentDir and at commit from OutstandingRequest |
| **G_S ⇒ sharersMask ≠ 0** | `ResidentDir::validateCanonical` (L159–160) | `panic_if(sharersMask == 0)` | Fatal panic if empty sharersMask in G_S |
| **G_I ⇒ sharersMask = 0** | `ResidentDir::validateCanonical` (L162–164); `processInvalidationAck` (L1297–1300) | `panic_if(sharersMask != 0)`; canonicalization `G_S→G_I` when last sharer acked | `entry.sharersMask &= ~nodeBit` in invalidation ack; automatic state transition to G_I when mask reaches zero |
| **Exclusive entry owner extracted from sharersMask** | `ownerFromSharers` (ResidentDir.cc:35–38) | `__builtin_ctzll(e.sharersMask)` after asserting popcount == 1 | Single-bit mask directly encodes the exclusive owner node ID |

**Proof sketch.** *Epoch monotonicity:* For any line PA, let `E` be the committed epoch in `DirEntry.epoch`. The only site that writes `DirEntry.epoch` is `commitIntendedResult`, which sets it to `normalizeEpoch(ost.reservedEpoch)`. The `ost.reservedEpoch` was previously allocated by `allocateReservedEpoch` as `normalizeEpoch(entry.epoch + 1)`. Thus successive committed epochs are `E_0, E_0+1, E_0+2, ...` modulo `2^N` in half-range arithmetic. `checkEpochForLine` uses `isNewerEpoch` to reject any request/response whose epoch is strictly older than the committed epoch (delta > 0 and < half_range), so stale messages are never applied. *sharersMask correctness:* `commitIntendedResult` writes `ost.intendedSharersMask` (or a one-hot mask derived from `intendedOwnerNode`) into `entry.sharersMask` and asserts the exclusive-state one-hot property. The only other writer is the invalidation-ack path (line 1294), which clears a single bit and transitions G_S→G_I when the mask reaches zero. The static `validateCanonical` on ResidentDir write-back re-checks all three state/mask relationships, creating a double-validation barrier between the protocol controller and the backing store.
