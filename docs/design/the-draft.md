# UBCC 正式交付文档内部草稿与叙事台账

> 本文件仅用于内部写作、审阅和后续同步，不属于正式交付件。三份正式交付件中的
> `[TODO-Rxx]` 仅引用本文件对应条目，不得在正式交付件中出现本文件名称、内部限制、
> 运行命令、开发过程或证据哈希。

## 1. 发布定位

三份正式文档按“发布会”方式组织：先给客户能够直接理解和复述的结论，再给架构、
机制和必要数据；完整实验矩阵、开发过程和运行环境信息不进入正文。

统一主叙事：

1. UBCC 将跨节点目录和仲裁从节点内 HN-F 资源域中分离，形成独立、可扩展的全局一致性层。
2. ResidentDir 与 Backstore 形成分层元数据体系，在固定 SRAM 预算下扩展等效追踪容量。
3. EP-RNF、EP-SNF 与 UBAdapter 将 UBCC 接入节点内 CHI 域，支持远程读、所有权迁移和共享转写者路径。
4. 形式化验证与 52 项故障资格矩阵共同支撑安全性、活性和可恢复传输故障能力。
5. 三项性能指标全部达到冻结验收口径；指标 3 的胜场是冻结 HA-VI 可执行参考模型、2N1S、O3、单向完成语义和 L3 压力条件下的配对比较。

## 2. 术语约定

正式文档允许使用的核心术语限定如下：

| 术语 | 正式定义 |
|---|---|
| UBCC | 跨节点缓存一致性方案及其全局目录控制器；需区分时写“UBCC 方案”或“UBCC 控制器” |
| EP | 节点内 CHI 域与 UBCC 之间的端点扩展层 |
| EP-RNF | 代表跨节点一致性域参与节点内 snoop 的端点 |
| EP-SNF | 将节点内请求接入 UBCC 路径的服务端点 |
| UBAdapter | 节点内 CHI 端点与 UBIO 之间的消息适配组件 |
| UBIO | 承载 UBCC 控制器的运行模块 |
| ResidentDir | UBCC 的 SRAM 驻留目录 |
| Backstore | ResidentDir 冷元数据的后备存储 |
| HA-VI | 指标 3 使用的 VI 协议可执行参考模型 |
| Inner 域 | 节点内标准 CHI 一致性域 |
| Outer 域 | 由 UBCC 管理的跨节点一致性域 |
| 单向完成语义 | 根操作不以同步 ClearResp 作为完成条件的冻结语义 |
| 核心场景组 | TC228-TC230 等权聚合 |
| 代表场景组 | TC231-TC235 按冻结定义聚合 |
| 等效追踪容量 | ResidentDir 与已持久化 Backstore 元数据的去重覆盖量 |

正式正文不再使用 `OurCC`。历史结果文件名、脚本变量名和原始证据字段不改名，但不在
客户正文中展示。

## 3. 正式文档必须排除的内容

1. SHA-256、commit、diff hash、binary hash、dirty worktree、clean checkout 等开发证据标识。
2. Docker 命令、CPU 绑定、timeout、磁盘门槛、supervisor、日志路径和结果目录。
3. 调试 Marker，例如 `RECALL-DIAG`、`UPGRADE-DIAG`、`UBFAULT`、`TRACE-PERF`。
4. 第一次运行失败、磁盘门槛中止、crash、retry storm、barrier 卡住等试错过程。
5. 旧的指标 2 理论值 `810 ns -> 78 ns` 和修复前的弱 baseline。
6. “遗憾、仅、明显落后、严重不足、不能证明、不得扩大”等高频防御式句式。
7. 本地开发仓路径、gem5 子仓展开路径、测试脚本路径和源码行号。

## 4. 限制与不进入正式正文的材料

### 4.1 永久故障在线恢复

当前架构没有冗余 Home、dirty 数据副本和在线重配置。该能力不属于 Q1-Q5，也不作为
本次发布主张。正式文档只在交付范围表中写“永久 Home 故障后的在线服务恢复不在本次
交付范围”，不展开缺陷分析。

### 4.2 完整 ARMv8 axiomatic/herd7 证明

R07 已在可执行 O3 范围完成。完整 ARMv8 axiomatic/herd7 证明留作合同另行要求时的
扩展项，不在正式正文中作为弱点展开。

### 4.3 HA-VI 范围

指标 3 使用 HA-VI 可执行参考模型，不等同于客户物理芯片实测。正式文档在摘要和指标 3
结论各写一次范围限定，不在每节重复辩护。

### 4.4 确定性重复

五对配对运行用于模型复现和 AB/BA 顺序平衡，不报告 t-test、p-value 或置信区间。
该统计约定留在内部证据说明，正式正文只写“五对配对运行”。

### 4.5 指标 2 的 TC138

TC138 为 -13.333333%，按冻结聚合规则保留。正式文档不写“失败”或“退化”，而写：
“TC138 体现了 dirty handoff 场景下的机制权衡；其结果完整纳入等权平均，聚合指标仍为
64.759276%。”该材料承担“排除选择性过滤”的论证职责。

### 4.6 指标 3 的局部子项

TC232 hot-key read 略偏 HA-VI，write 明显偏 UBCC；TC234 queued-token store 子阶段不
作为主值。正式正文只解释冻结主值聚合边界，不罗列所有不参与计权的子阶段。完整子项
可放附录。

### 5.1 指标 1/2 结果分层说明

正式合同总分保持冻结口径：指标 1 由 TC131 计分，指标 2 由 TC135-TC140 和 TC217
计分。TC120-TC129、TC130-TC134、TC141、TC142-TC147 作为正式支撑结果进入正文，
但不在缺少冻结权重的情况下混入合同总分。

该调整不是删除实验，而是明确每组实验的论证职责：

- TC120-TC124：访问模式和低/高复用条件；
- TC125-TC129：Backstore 生命周期正确性；
- TC130-TC134：真实容量压力和多拓扑；
- TC141：shared-writer recovery 资格门禁；
- TC142-TC147：16N1S 代表应用价值。

TC142-TC147 使用外部冻结 16N1S 一轮正式矩阵，三个 profile 共 18/18 PASS。由于当前
只有一轮，不报告跨轮 CV；正式正文报告端到端均值和相对降幅，不把它们定义为新的合同
总分。
